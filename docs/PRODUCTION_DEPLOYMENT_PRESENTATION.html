Implementation

Migration Path: Current Stack → Production

🗺️
Timeline estimate: 1–3 days for Option A (DigitalOcean)
The biggest effort is implementing the Storage Adapter for Spaces/S3. Database migration is a single pg_dump/restore. Frontend stays on Vercel unchanged.
1

Implement the Storage Adapter (2–4 hours)

Create IStorageProvider interface and S3StorageProvider class using @aws-sdk/client-s3. DigitalOcean Spaces and Cloudflare R2 are both S3-compatible — the same adapter covers all three. See docs/CaseStudy_ORM_and_Portability.md for the exact code pattern.

2

Export PostgreSQL from Supabase (30 minutes)

Run pg_dump $SUPABASE_DATABASE_URL > lms_backup.sql. Import to DigitalOcean Managed PG with psql $NEW_DATABASE_URL < lms_backup.sql. No schema changes needed — same Postgres, same raw SQL.

3

Migrate files from Supabase Storage → New Provider (1–2 hours)

Use rclone to bulk-copy your existing buckets. All your stored references are in bucket/path format (from the private storage migration) so they map directly to the new bucket.

4

Deploy Backend API (2–3 hours)

Dockerize (or use PM2) your Express server. Deploy to Droplet or EC2. Set environment variables: DATABASE_URL, STORAGE_ENGINE=s3, S3_ENDPOINT, S3_BUCKET, AWS/Spaces credentials, JWT_SECRET, NODE_ENV=production.

5

Update Frontend Config & DNS (30 minutes)

Update REACT_APP_API_URL in Vercel to point to new backend. Update DNS to point domain to new server IP. Run both stacks in parallel for 24–48 hours to verify, then decommission Render/Supabase.

🚨
One thing to absolutely avoid in production
Do NOT use Render.com for file storage. Their $0.30/GB pricing means 500 GB = $150/month in storage alone. DigitalOcean Spaces does the same for $10/month — a 15× cost difference. Render is excellent for staging; migrate before going to production.
✅
The core advantage: your code is already portable
Because you use raw SQL via the pg driver (not Supabase-specific), your database will move to any PostgreSQL host with a single DATABASE_URL change. Once you implement the Storage Adapter Pattern for file uploads, your entire infrastructure becomes a configuration exercise — not a code rewrite. You can change providers at any time without touching business logic.
